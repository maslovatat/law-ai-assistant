# AI Legal Assistant — демонстрационный прототип

Локальный веб-сервис: пользователь описывает юридическую проблему → ИИ задаёт уточняющие вопросы → принимает файлы →
собирает структурированные факты → оценивает качество подготовки → составляет претензию (DOCX/PDF, версии) →
**демо**-подписание → **демо**-отправка → история отправлений.

> ⚠ **Важно.** Подписание (имитация Госключа) и отправка (имитация Почты России) — **симуляции**. Демо-подпись не является УКЭП/УНЭП
> и не имеет юридической силы; реальные письма не отправляются. Правовая база — небольшой набор положений в пересказе, **не сверенный**
> с официальными текстами. Используйте только вымышленные персональные данные.

## 1. Установка (Windows)
1. Установите **Python 3.10+** (python.org, галочка *Add to PATH*).
2. Дважды щёлкните **`setup.bat`**: создаст окружение `.venv`, поставит зависимости, создаст `.env`.
   Готовая сборка интерфейса лежит в `frontend/dist`, Node.js для запуска **не нужен** (только для разработки интерфейса).
3. (Необязательно) для распознавания текста на фото установите **Tesseract OCR** (сборка UB-Mannheim) с языком *Russian*.
   Если `tesseract.exe` не в PATH, укажите путь в `.env`: `TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe`.
   Без Tesseract текстовые PDF и DOCX читаются, а для фото приложение сообщит, что OCR недоступен.

## 2. Запуск и вход
`run.bat` откроет http://127.0.0.1:8000. Демо-аккаунт: **demo@example.com / demo12345** (или зарегистрируйтесь). Linux/macOS: `./run.sh`.

## 3. Демо-сценарии
На главной нажмите **«Загрузить демо-данные»**: появятся 3 дела с диалогами и тестовыми файлами:
1. Неисправный холодильник (чек, гарантийный талон), готово к претензии.
2. Повреждение авто на парковке (фото, смета), готово к претензии.
3. Некачественный ремонт: диалог не завершён, продолжите в чате (отвечайте на вопросы по одному).

Путь: дело → **Составить претензию** → правка (новая версия) → **DOCX/PDF** → **Перейти к подписанию** → подтвердить →
**Перейти к отправке** → подтвердить → «Отправления» (статусы сменяются сами примерно за 12 секунд; шаг задаётся `DEMO_DELIVERY_STEP_SECONDS`).

## 4. Работа с ИИ
По умолчанию `AI_PROVIDER=demo`: без интернета и ключей вопросы и извлечение фактов выполняют правила. Это хорошо работает на сценариях выше,
но на свободном тексте заметно проще настоящей модели.

**Бесплатный ключ Gemini:** https://aistudio.google.com/apikey → создайте ключ → вставьте в `.env`:
```
AI_PROVIDER=gemini
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-2.5-flash
```
Перезапустите `run.bat`. Провайдер и модель можно сменить на странице **«Настройки ИИ»** (там же проверка подключения).
Другие: `AI_PROVIDER=groq` + `GROQ_API_KEY`; `AI_PROVIDER=ollama` (локально, `ollama pull qwen2.5:7b`).
Если API недоступен, чат сообщает об этом и продолжает в демо-режиме; после ошибки ключа/лимита провайдер отключается на 90 секунд (без повторных запросов).
Имена моделей меняются: при ошибке модели проверьте актуальное имя в документации провайдера.

**Экономия токенов:** один запрос на сообщение; в него входят последние 6 сообщений, известные факты (JSON), 1–2 поля «спросить сейчас»,
краткие описания файлов, распознанный текст документов (фрагментами) и до 3 найденных фрагментов норм; ответ до 700 токенов.
Документы читаются локально, а их текст передаётся выбранному провайдеру, чтобы модель извлекла сведения; при загрузке файла факты
заносятся в карточку автоматически (с пометкой «из документа») и проверяются пользователем.
Недостающие сведения, оценка и текст претензии вычисляются кодом; ИИ не перезаписывает сведения, введённые пользователем.
**ИИ-редактор:** кнопка в документе или команда в чате («добавь…», «исправь…») переписывает претензию подробнее и официальнее
и создаёт новую версию; суммы, даты и ФИО проверяются кодом после ответа модели.

## 4.1 Публичный API (внешние приложения)

Ключи создаются в интерфейсе: **Настройки → API-доступ**. Ключ показывается один раз, хранится в виде хеша
и отзывается кнопкой. Запросы идут на `/api/v1/*` с заголовком `X-API-Key: ak_…` (или `Authorization: Bearer ak_…`),
лимит — 120 запросов в минуту на ключ. Каждый ключ видит только дела своего владельца.

```bash
curl -X POST http://127.0.0.1:8000/api/v1/cases \
  -H "X-API-Key: ak_..." -H "Content-Type: application/json" \
  -d '{"title":"Спор с маркетплейсом"}'

curl -X POST http://127.0.0.1:8000/api/v1/cases/1/messages \
  -H "X-API-Key: ak_..." -H "Content-Type: application/json" \
  -d '{"message":"Привезли кирпич вместо видеокарты, покупал в магазине"}'
```

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/me` | профиль, число дел и активных ключей |
| GET / POST | `/api/v1/cases` | список дел / новое дело |
| GET | `/api/v1/cases/{id}` | дело: факты, оценка, документы |
| POST | `/api/v1/cases/{id}/messages` | сообщение помощнику → ответ + дело |
| POST | `/api/v1/cases/{id}/files` | загрузка чека/договора (multipart) |
| POST | `/api/v1/cases/{id}/documents` | составить претензию (`{"type":"claim"}`) |
| GET | `/api/v1/documents/{id}` | документ и все версии |

Интерактивная схема — `http://127.0.0.1:8000/docs`, спецификация — `/openapi.json`.

## 5. Архитектура
```
backend/app/
  routers/   HTTP-API          ai/       провайдеры Gemini/Groq/Ollama, demo_engine, orchestrator
  legal/     поля, kb.json, поиск, Legal Confidence Engine
  docs/      претензия из шаблона и фактов, DOCX/PDF, версии
  dispatch/  SignatureProvider / DeliveryProvider + Mock     files/  загрузки, OCR, анализ, противоречия
  cases.py   Legal Case Manager     migrations/*.sql
frontend/ (React+Vite+TS+Tailwind, сборка в dist)   templates/   storage/ (не отдаётся по URL)   tests/
```
Оценка 0–100: полнота 30, документы 20, отсутствие противоречий 20, актуальность норм 10 (максимум 70, пока нормы не сверены), требования 10,
согласованность 10. ≥85 продолжать; 65–84 проверка; <65 юрист. Критические риски (вред здоровью, уголовные признаки, несовершеннолетние,
недвижимость, срок давности >3 лет, сумма >500 000 ₽, противоречия с проверенными документами, нет норм в базе) → юрист независимо от оценки,
создание документа блокируется. Это демонстрационная оценка, а не вероятность правильности.

Подписанная версия неизменяема (триггер SQLite); правка создаёт новую версию, подписывать заново. Повторные нажатия «подписать/отправить» идемпотентны.

## 6. Что нужно для реальной работы
Госключ и Почта России **не подключены**: реализуйте `SignatureProvider` и `DeliveryProvider` (`backend/app/dispatch/providers.py`) по документации
операторов или через СМЭВ. Адреса API намеренно не выдуманы. Правовую базу `legal/kb.json` нужно заменить проверенным источником.
