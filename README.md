# AI Legal Assistant - демонстрационный прототип

Это локальный веб-сервис, который помогает разобраться с юридической проблемой. Пользователь описывает ситуацию, ИИ задаёт уточняющие вопросы и принимает файлы. Потом сервис собирает факты в структурированном виде и оценивает, насколько хорошо подготовлены материалы. После этого можно составить претензию в формате DOCX или PDF, причём с версиями. Дальше идёт демо-подписание и демо-отправка, а все отправления сохраняются в истории.

Подписание и отправка здесь только имитируются. Демо-подпись не является УКЭП или УНЭП и не имеет юридической силы. Реальные письма никуда не уходят. Правовая база - это набор положений в пересказе, и он не сверялся с официальными текстами.

## 1. Установка (Windows)
1. Установите Python 3.10+ (python.org, галочка *Add to PATH*).
2. Дважды щёлкните `setup.bat`. Он создаст окружение `.venv`, поставит зависимости, создаст `.env`.
   Готовая сборка интерфейса лежит в `frontend/dist`, Node.js для запуска не нужен (только для разработки интерфейса).
3. Для распознавания текста на фото установите Tesseract OCR (сборка UB-Mannheim) с языком Russian.
   Если tesseract.exe не в PATH, укажите путь в .env: `TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe`.
   Без Tesseract текстовые PDF и DOCX читаются, а для фото приложение сообщит, что OCR недоступен.

## 2. Запуск и вход
Запустите run.bat, и откроется адрес http://127.0.0.1:8000. Демо-аккаунт: demo@example.com / demo12345 (или зарегистрируйтесь). На Linux/macOS запускайте через ./run.sh.

## 3. Демо-сценарии
На главной нажмите «Загрузить демо-данные». Появятся дела с диалогами и тестовыми файлами.

Путь: дело → Составить претензию → правите текст → DOCX/PDF → Перейти к подписанию → подтвердить →
Перейти к отправке → подтвердить → «Отправления» (статусы сменяются сами примерно за 12 секунд; шаг задаётся через переменную `DEMO_DELIVERY_STEP_SECONDS`).

## 4. Работа с ИИ
По умолчанию AI_PROVIDER=demo. Это значит, что без интернета и ключей вопросы и извлечение фактов выполняют правила. Это на свободном тексте заметно проще настоящей модели.

**Бесплатный ключ Gemini:** https://aistudio.google.com/apikey → создайте ключ → вставьте в `.env`:
```
AI_PROVIDER=gemini
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-2.5-flash
```
Перезапустите run.bat. Провайдер и модель можно сменить на странице «Настройки ИИ» (там же проверка подключения).
Другие: `AI_PROVIDER=groq` + `GROQ_API_KEY`; `AI_PROVIDER=ollama` (локально, `ollama pull qwen2.5:7b`).
Если API недоступен, чат сообщает об этом и продолжает в демо-режиме; после ошибки ключа/лимита провайдер отключается на 90 секунд (без повторных запросов).
Имена моделей меняются: при ошибке модели проверьте актуальное имя в документации провайдера.

Экономия токенов. На каждое сообщение уходит один запрос. В него входят последние 6 сообщений, известные факты в JSON, 1–2 поля «спросить сейчас»,
краткие описания файлов, распознанный текст документов фрагментами и до 3 найденных фрагментов норм. Ответ ограничен 700 токенами.
Документы читаются локально, а их текст передаётся выбранному провайдеру, чтобы модель извлекла сведения. При загрузке файла факты заносятся в карточку автоматически с пометкой «из документа» и проверяются пользователем.
Недостающие сведения, оценка и текст претензии вычисляются кодом. ИИ не перезаписывает сведения, введённые пользователем.
ИИ-редактор - это кнопка в документе или команда в чате «добавь…», «исправь…» переписывает претензию подробнее и официальнее и создаёт новую версию. Суммы, даты и ФИО проверяются кодом после ответа модели.

## 4.1 Публичный API для внешних приложений

Ключи создаются в интерфейсе через Настройки → API-доступ. Ключ показывается один раз, хранится в виде хеша и отзывается кнопкой. Запросы идут на /api/v1/* с заголовком X-API-Key: ak_… или Authorization: Bearer ak_…
Лимит - 120 запросов в минуту на ключ. Каждый ключ видит только дела своего владельца.

```bash
Пример создания дела через curl:
curl -X POST http://127.0.0.1:8000/api/v1/cases \
  -H "X-API-Key: ak_..." -H "Content-Type: application/json" \
  -d '{"title":"Спор с маркетплейсом"}'

Пример отправки сообщения:

curl -X POST http://127.0.0.1:8000/api/v1/cases/1/messages \
  -H "X-API-Key: ak_..." -H "Content-Type: application/json" \
  -d '{"message":"Привезли кирпич вместо видеокарты, покупал в магазине"}'
```

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/me` | профиль, число дел и активных ключей |
| GET / POST | `/api/v1/cases` | список дел / новое дело |
| GET | `/api/v1/cases/{id}` | дело: факты, оценка, документы |
| POST | `/api/v1/cases/{id}/messages` | сообщение помощнику → ответ + дело |
| POST | `/api/v1/cases/{id}/files` | загрузка чека/договора (multipart) |
| POST | `/api/v1/cases/{id}/documents` | составить претензию (`{"type":"claim"}`) |
| GET | `/api/v1/documents/{id}` | документ и все версии |

Интерактивная схема доступна по адресу `http://127.0.0.1:8000/docs`, спецификация лежит в `/openapi.json`.

## 5. Архитектура
```
В папке backend/app/ лежат routers для HTTP-API, ai с провайдерами Gemini, Groq и Ollama, а также demo_engine и orchestrator. Там же legal с полями, kb.json, поиском и Legal Confidence Engine. Дальше docs, где претензия собирается из шаблона и фактов, делаются DOCX и PDF и хранятся версии. Есть dispatch с SignatureProvider и DeliveryProvider плюс Mock. Ещё files для загрузок, OCR, анализа и поиска противоречий. Отдельно лежат cases.py с Legal Case Manager и migrations с SQL-файлами. Во frontend/ находится React с Vite, TypeScript и Tailwind, сборка кладётся в dist. Ещё есть templates, storage (он не отдаётся по URL) и tests.

Оценка идёт от 0 до 100. Полнота даёт 30, документы 20, отсутствие противоречий 20, актуальность норм 10 (максимум 70, пока нормы не сверены), требования 10 и согласованность 10. Если набралось 85 и больше, можно продолжать. От 65 до 84 нужна проверка. Меньше 65 — передаём юристу. Критические риски (вред здоровью, уголовные признаки, несовершеннолетние, недвижимость, срок давности больше 3 лет, сумма больше 500 000 ₽, противоречия с проверенными документами, нет норм в базе) ведут к юристу независимо от оценки, а создание документа блокируется. Это демонстрационная оценка, а не вероятность правильности.

Подписанная версия неизменяема, за это отвечает триггер SQLite. Правка создаёт новую версию, и подписывать нужно заново. Повторные нажатия «подписать» или «отправить» идемпотентны.
```

## 6. Что нужно для реальной работы
Госключ и Почта России не подключены. Чтобы их подключить, нужно реализизовать `SignatureProvider` и `DeliveryProvider` в (backend/app/dispatch/providers.py) по документации
операторов или через СМЭВ. Адреса API намеренно не выдуманы. Правовую базу legal/kb.json нужно заменить проверенным источником.

## 7. Тесты и разработка
Запустить pytest. Там 12 тестов, среди них сценарий из 19 шагов, изоляция пользователей, валидация файлов, недоступность API и передача юристу. Для интерфейса зайти в cd frontend, сделать npm install и npm run dev, порт 5173. Сборка делается через npm run build.
